# LG-Inventory Feature Update Guide

The updated application includes a password show/hide button on the login screen, procurement information for inventory items, monthly inventory and sales report downloads, and QR-code sharing for reports.

## New inventory fields

Each newly created or edited inventory item stores `procurementSource` as either `DA` or `Farm Purchase`. When `Farm Purchase` is selected, `procurementCost` stores the purchase cost as a numeric value. Existing Firestore documents remain compatible because the interface displays `Not specified` when older records do not yet contain these fields.

## Reports

Open **Reports** from the sidebar. Select one month, one report type (Inventory or Sales), and one format (Excel or PDF), then click **Create File and QR Code**. Inventory reports include item name, type, stock unit, quantity, stock type, procurement source, farm cost, and last stock update. Sales reports include item name, fish/plant type, quantity sold, unit, income, date of sale, and notes. Archived records are excluded.

## Required dependency installation

The report generator uses `PhpSpreadsheet` for real `.xlsx` files, `Dompdf` for PDF files, and `SimpleSoftwareIO\QrCode` to generate QR codes. On a machine with PHP and Composer installed, run:

```bash
composer update phpoffice/phpspreadsheet dompdf/dompdf simplesoftwareio/simple-qrcode
composer dump-autoload
```

If this is a fresh clone, use `composer install` after the lock file has been regenerated by the command above. PhpSpreadsheet may require PHP extensions such as `zip`, `xml`, `gd`, and `mbstring`, depending on the operating system.

Then rebuild the frontend assets:

```bash
npm install
npm run build
```

## QR-code sharing

The Reports page now generates one exact report at a time. The admin selects the month, chooses Inventory or Sales, and chooses Excel or PDF. The system then shows a direct **Download This File** button and one QR code for that exact file. The QR label identifies the report type, month, and format, for example `Sales Report — June 2026 — PDF`. Scanning it opens a sharing page with only the matching download button. To download another month, return to the Reports page, select the other month, and generate a new file and QR code. The normal direct download button remains available for the admin.

The QR feature uses a QR-code package to render the QR image and Laravel temporary signed URLs to bind the QR code to the selected report type, format, and month. A QR code cannot be edited to access another month because the signature becomes invalid. The application must be hosted on a reachable HTTPS domain for phone scanning to work. A QR code cannot reliably open `localhost` or a private LAN address from another device.

## Firestore considerations

No migration is required because Firestore is schemaless. Existing inventory documents can continue to work. New or edited documents receive the procurement fields automatically. If a record was created before this update, edit and save it if you want to assign its procurement source.

## Important validation note

The current update adds the procurement source as a required field in the inventory create and edit forms. The farm cost is required by the browser and stored only for farm purchases; the backend accepts a zero cost if a custom request bypasses browser validation. If your policy requires a positive cost, change the validation rule for `procurementCost` to `required_if:procurementSource,Farm Purchase|numeric|min:0.01` in `InventoryController.php`.

## Testing checklist

After installing dependencies, verify the following in the browser:

1. On the login page, click **Show** and **Hide** and confirm that the password input changes between masked and visible text.
2. Create a DA inventory item and confirm that the table shows `DA` without a farm cost.
3. Create a Farm Purchase item, enter its cost, and confirm that both the source and cost appear in the inventory table.
4. Edit an existing item and confirm that its procurement values populate the form.
5. Open Reports, select a month, select Inventory, select Excel, and click **Create File and QR Code**.
6. Confirm that **Download This File** downloads the selected Excel report and that the label identifies the correct month and format.
7. Scan the QR code and confirm that the page offers only the matching Excel download.
8. Repeat for Sales/PDF and confirm that the correct sales PDF downloads.
9. Select a different month and confirm that the new report and QR code use that month.
10. Confirm that archived records are excluded and that an expired QR link is rejected.
11. Confirm that the application is hosted on a reachable HTTPS domain; QR codes will not work externally with `localhost`.
